# AI 简历填表助手

**维护一份标准简历，在不同招聘网站重复使用。能自动填的交给插件，不确定的自己选，填不了的直接复制。**

这是一个运行在 Chrome / Edge 侧边栏中的浏览器扩展，面向校招、社招和企业官网网申。项目正在持续改进跨网站的字段识别和填写能力，目前没有“所有招聘网站通用”的兼容性承诺。

你可以让插件处理当前页面，也可以自己打开一条经历的编辑区，从标准简历里选择任意一条填入。填写范围与来源由用户控制，最终申请由用户检查并提交。

[安装与使用](#安装与使用) · [填写方式](#填写方式) · [工作原理](#工作原理) · [已知限制](#已知限制) · [参与开发](CONTRIBUTING.md)

## 主要功能

| 功能 | 当前用途 |
| --- | --- |
| 标准简历与多模板 | 维护个人信息、教育、实习、工作、项目、获奖、语言等资料，为不同岗位准备不同模板 |
| 指定经历选填 | 框选网页中的一条编辑区，选择任意来源记录填入，不依赖来源和目标的排列顺序 |
| 随时复制 | 复制单字段、整条经历，或展开完整文字手动选择；无需模型和网页选区 |
| 整页与增量填写 | 填写可识别的字段，或保留已有内容后补填；提供停止入口 |
| 字段语义匹配 | 本地规则结合标签、区块和选项判断含义；模型可补充未确定的映射 |
| 常见控件处理 | 原生输入框、下拉、单选、多选、富文本，以及部分搜索下拉和日期选择器 |
| 简历导入与备份 | 手工编辑、使用模型整理简历文本或带文字层的 PDF，导入导出简历文档和模板备份 |
| 本机附件 | 配置照片、简历和作品附件，匹配页面文件控件后本地选择 |
| 映射结果与日志 | 查看字段来源、填写状态和诊断信息；支持保存、删除字段概念记忆 |

## 安装与使用

### 1. 下载并加载扩展

从[本仓库](https://github.com/MTuoeAry/AI-Resume-Form-Filling-Assistant)下载 ZIP 并解压，或者克隆：

```sh
git clone https://github.com/MTuoeAry/AI-Resume-Form-Filling-Assistant.git
cd AI-Resume-Form-Filling-Assistant
```

1. 在 Chrome 打开 `chrome://extensions/`，或在 Edge 打开 `edge://extensions/`。
2. 开启开发者模式，点击“加载已解压的扩展程序”。
3. 选择包含 `manifest.json` 的项目根目录。
4. 打开需要填写的招聘网页，点击扩展图标打开侧边栏。

**使用扩展不需要安装 Node.js，也没有构建步骤。** Node.js 和 npm 仅用于开发测试。

### 2. 准备标准简历

在“标准简历”页创建或选择模板，点击“打开简历配置页”，在宽页面维护资料。

- 可直接手工填写，无需配置模型。
- 配置模型后，可让模型整理粘贴的简历文本或带文字层的 PDF；导入后请核对。
- 教育、实习、工作等经历分别维护，不要把所有内容塞进同一个技能描述。
- 语言能力区分语种、熟练程度、考试类型、考试等级、成绩和 CEFR 等级；旧版考试原文仍保留。

需要备份时，可导出单份 `.airesume.json`，或在模板管理中导出全部模板。备份不含模型配置、API Key 和本机附件，换电脑后这些内容需单独配置。

### 3. 按页面情况选择填写方式

如果网站要求填完一条才能新增下一条，可以使用“选填与复制”，由自己控制新增和保存。若页面结构清晰、字段已经展开，可尝试整页或增量填写。

## 填写方式

### 选填与复制

这是按“网页目标 + 简历来源”操作的方式，适合需要自己控制经历条目的场景。

1. 在网页手动打开或新增**一条**教育、项目、工作等经历的编辑区。
2. 切换侧边栏到“选填与复制”，点击“选择网页区域”，框选这条记录的输入区域。
3. 在侧边栏展开对应资料，选择任意一条经历，点击“填入选中区域”。例如，可以把简历中的第 3 个项目填进网页的第 1 个项目编辑区。
4. 默认保留已有内容；需要替换时勾选覆盖选项。
5. 核对网页内容，自己保存、新增下一条，再选择下一份资料。

一次应选择一条记录，单选和多选组应完整框入。目标控件发生重建、页面切换或模板变化后可能需要重新选区。这条流程不自动新增、保存或提交申请。

**自动填写失效时仍可复制。** 每条资料支持单字段复制、整条复制、查看完整内容及手动选择文字。复制不依赖选区、模型或填充任务完成。

### 自动填充

| 入口 | 行为 | 使用前注意 |
| --- | --- | --- |
| 开始填充 | 按当前模板填写可识别字段，允许覆盖 | 先确认模板及页面已有内容 |
| 增量填入 | 跳过已有值，补填能够确定的空字段 | 不会自动修正先前填错的非空内容 |
| 选区填入 | 只处理框选范围内的字段 | 与“选填与复制”不同，这里不显式选择某条来源记录 |

整页流程还会尝试展开明确的折叠区块，并对部分重复经历逐条处理。网站保存、新增和异步验证的行为差异很大，不能确定推进结果时会停止并提示人工处理。

运行中可点击“停止填充”，停止后续操作并保留已写入内容。停止请求若未得到网页响应，界面会提示；这不代表网页上的任务已经确认结束。

## 可选：配置模型

侧边栏右上角打开模型设置，填写服务地址、模型名称和 API Key。项目提供 DeepSeek 配置模板，也支持实现了兼容 Chat Completions 协议的服务。

模型负责简历文本整理和部分字段映射；填写控件的动作由浏览器内的内容脚本执行。模型服务的费用、可用性和数据处理规则由所选服务决定。

未配置模型或模型请求失败时，插件仍可使用本地规则处理确定的字段；资料查看和复制始终可用。兼容接口并不代表每个模型服务都已测试，具体配置以服务提供方的说明为准。

## 工作原理

```text
标准简历 / 当前模板
          ↓
识别网页区块、记录、标签和控件
          ↓
本地概念规则与字段映射 → 必要时请求模型补充
          ↓
核对来源路径、条目归属和控件兼容性
          ↓
执行填写、读取结果、展示状态
          ↓
用户检查、补填并提交
```

“字段含义”和“来源记录”是两个不同的问题。例如，先识别某个字段是奖项名称，再确定它属于哪条获奖记录。“外语能力类型”应指向语言名称；“英语能力等级”则需要结合页面选项判断是在问熟练程度、考试等级还是 CEFR。

目前已有概念词典、映射校验、重复记录对齐和缓存版本控制，但这些约束仍在完善。具体实现、开发要求和未完成项分别见 [HANDOFF](HANDOFF.md)、[映射可靠性实施规范](MAPPING_RELIABILITY_IMPLEMENTATION.md)和[路线图](ROADMAP.md)。

## 已知限制

- 自定义下拉、异步搜索、级联选择器和保存后重建的编辑区仍可能识别或操作失败。
- 标签不清楚、来源缺失、同名经历无法区分时，可能需要用户选择、补充资料或复制。
- 来源只精确到年月而目标要求具体日期时，不应自动补造日期。
- 扫描版或图片型 PDF 需要先做 OCR；项目不提供内置 OCR。
- 上传后的裁剪、文件校验和网站二次确认通常仍需手动完成。
- 没有发布经过全面验收的招聘网站兼容列表；本地虚构表单和扩展测试通过，不等于对应招聘网站已经通过。

## 数据与权限

| 数据 / 权限 | 用途与边界 |
| --- | --- |
| 简历、模板、模型配置 | 保存在浏览器扩展本地存储中，不通过 Chrome Sync 同步 |
| 本机附件 | 保存在扩展本机数据库中，填写文件控件时交给目标网站 |
| 模型请求 | 使用模型导入或映射时，会向所配置的服务发送相应简历内容和页面字段信息 |
| 网页访问与 scripting | 在用户操作的 HTTP(S) 页面注入内容脚本，识别并填写表单 |
| sidePanel | 显示侧边栏界面 |
| clipboardWrite | 响应用户的复制操作；没有申请剪贴板读取权限 |
| 诊断导出 | 选择目录后可保存运行日志；共享前仍需检查个人信息 |

本项目无需部署自有后端。选择在线模型后，相应处理不再完全在本机进行。API Key 由扩展后台读取并用于模型请求，不作为网页字段映射数据交给招聘页面脚本。

## 常见问题

**更新代码后，为什么页面还是旧行为？**

在扩展管理页重新加载扩展，并在保存或备份未保存内容后刷新招聘网页。已注入的旧脚本不会因为磁盘文件变化而自动更新。

**为什么点了增量填入，错误内容没有被修正？**

增量模式会保留已有值。核对正确来源后，可以清空错误字段再补填，或在指定记录选填时明确启用覆盖。

**为什么显示有映射，页面却没填上？**

确定来源和成功操作控件是两个阶段。检查该字段的最终状态、页面选项是否加载，以及是否出现验证错误；失败时可从侧边栏复制补填。

**字段映射错了怎么办？**

先查看字段标签、来源路径和当前版本。可使用指定记录选填或复制完成当前申请。反馈问题时附上脱敏的字段示例和日志，不要直接上传整份真实简历。

## 开发与验证

开发环境需要 Node.js 20 或更新版本。测试依赖使用仓库锁文件安装：

```sh
npm ci
npm test
npm run test:e2e
```

E2E 需要可用的 Chrome，可通过 `CHROME_PATH` 指定路径。它使用独立测试环境加载扩展；测试说明和提交检查见 [CONTRIBUTING.md](CONTRIBUTING.md)。

本轮在当前源码运行的本地结果：**272 项 Node 测试通过，6 项 Chrome 扩展 E2E 通过**。这是固定时间点的回归结果，真实招聘网页仍需单独验收；后续结果以实际测试和仓库 CI 为准。

项目主要文件：

```text
manifest.json               扩展配置
background.js               后台消息与模型请求
content.js / content.css    网页识别、填充与选区
popup.*                     侧边栏
resume-editor.*             独立简历编辑页
shared/                     数据模型、映射、记录对齐、控件与存储模块
tests/                      单元、DOM 集成和 Chrome 扩展测试
```

`modules/`、`templates/` 和模板管理页面保留了早期问卷模板相关实现，不是当前标准简历填写的主要入口。
